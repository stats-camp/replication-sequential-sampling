Overview
Reshidi et al. (2024) The code in this replication package constructs “Sequential Sampling by Indi-
viduals and Groups: An Experimental Study,” which has been deposited in AEA Data and Code
Repository as openicpsr-208222 Reshidi et al. (2024). The data were collected by the authors. One
main file runs the code to generate all the analyses presented in the main body of the paper: two
figures, three tables, and three results presented in footnotes. Another file runs the code to generate
all the analysis presented in the online appendix: five figures and ten tables.


Data Availability and Provenance Statements
The data used in the paper were generated by an experiment conducted with 130 participants at
the Princeton Experimental Laboratory for the Social Sciences (PExL). All sessions were conducted
between October 13th and December 7th 2018. The experiment was programmed using oTree, as
described in oTree—An open-source platform for laboratory, online, and field experiments” Chen
et al. (2016).

Dataset Description
Below, we describe each variable in each dataset.

group_voting.dta
Main Variables
   • s n- Session number. From 1 to 13, all sessions we had for all treatments.
   • sub n- Subsession, or, round number. Always from 1 to 30 in each session.
   • g id sub- Group id in the round. This is meaningless in individual treatments.
   • p id- Participant’s unique id.
   • treatment- From 1 to 3. The treatment number also indicates the number of votes requested.
     1 indicates individual decisions, 2 indicates majority, and 3 indicates unanimity.
   • final sec- The time, in seconds, when the pivotal vote was cast. For the individual treatment,
     this is simply the time at which the individual voted.
   • v- From 0 to 1. Indicates the probability of A when the pivotal vote was cast.
   • p- From 0.5 to 1. Indicates the posterior that the participants saw when the pivotal vote was
     cast. It is equal to v when v > 0.5 and equal to 1 − v when v < 0.5.
   • decision- Indicates the group or individual decision. It can be either A or B.
   • state- Indicates the correct state in that round. 0 corresponds to A, and 1 corresponds to B.
   • t1-t17- Indicates the time when the individual vote was cast. t1 corresponds to the first vote
     from this participant within the round. t2 corresponds to the second vote, if such a vote was
     cast, and so on. These are relevant only for the majority and unanimity treatments, as they are
     the only ones that permit multiple votes within a round.

  • m1-m17- Indicates what the vote was cast on. It can take values equal to A, W or B.

  • v1-v17- Indicates the probability of A when the vote was cast.
  • p1-p17- Indicates the posterior when the vote was cast. p is simply equal to v when v > 0.5
    and equal to 1 − v when v < 0.5.


Variables From Additional Elicitations
  • p kept1- Indicates the number of points the participant kept for herself the first time she played
    the dictator game. It can range from 0 to 200.
  • p rec1- Indicates the number of points the participant received after the first dictator game. It
    can range from 0 to 200.
  • p kept2- Indicates the number of points the participant kept for herself the second time she
    played the dictator game. It can range from 0 to 100.
  • p rec2- Indicates the number of points the participant received after the first dictator game. It
    can range from 0 to 100.
  • p inv1- Indicates the number of points the participant invested the first time she played the
    risk elicitation game. It can range from 0 to 200.
  • paid1- Indicates whether the initial investment was successful.

  • p inv2- Indicates the number of points the participant invested the second time she played the
    risk elicitation game. It can range from 0 to 200.
  • paid2- Indicates whether the second investment was successful.


long_format.dta
  • sub n- Subsession, or, round number. Always from 1 to 30 in each session.

  • process time- Time ranging from 0 to 300. Each process was generated up to 5 minutes (300
    seconds), this variable captures the time of the process.
  • process v- From 0 to 1. Indicates the probability of A.
  • process p- From 0.5 to 1. Indicates the posterior of the process. It is equal to process v when
    process v> 0.5 and equal to 1−process v when process v< 0.5.
  • process slope- Equal to the slope of the process in the last 5 seconds.
  • process std- Equal to the standard deviation of the process in the last 5 seconds.
  • v1- Is equal to process time if a vote was cast in treatment 1 at that time. Otherwise, it is
    missing.
  • v2- Is equal to process time if a vote was cast in treatment 2 at that time. Otherwise, it is
    missing.
  • v3- Is equal to process time if a vote was cast in treatment 3 at that time. Otherwise, it is
    missing.

simulated_groups.dta
We simulate hypothetical groups of three participants by drawing data from our individual treatment.
For each round, we randomly group the 34 participants in our individual treatment into 11 groups of
3 participants, randomly discarding one. We do so 1, 000 times. Across all 30 rounds, 330,000 groups
are therefore simulated.

   • sub n- Subsession, or, round number. Always from 1 to 30 in each session.
   • p id- Participant’s unique id.
   • t1- Indicates the time when the individual vote was cast.
   • decision- Indicates the group or individual decision. It can be either A or B.

   • v- From 0 to 1. Indicates the probability of A when the pivotal vote was cast.
   • p1- Indicates the posterior when the vote was cast. p is simply equal to v when v > 0.5 and
     equal to 1 − v when v < 0.5.
   • g id sub- Group id in the round. This is meaningless in individual treatments.

   • iter- Indicates the interaction number of the simulation.
   • treatment- From 1 to 3. The treatment number also indicates the number of votes requested.
     1 indicates individual decisions, 2 indicates majority, and 3 indicates unanimity.


Computational Requirements List
  1. Software Requirements
        • Open the analysis .do files in stats.camp.
        • Analysis commands: estout (formats regression output for export) and cdfplot (creates CDF
          plots of variables).
  2. Summary
        • The approximate time needed to reproduce the analysis is 3 minutes.

  3. Details
        • The code was run on a PC with an AMD Ryzen 7 5800X 8-Core 3.80 GHz processor with
          64 GB or RAM. The operation system was Windows 10.
